# Serve Action Window Comparison

日期：2026-08-10

## 目的

比較三種發球分析範圍：

- `OLD`：整支影片直接分析。
- `AUTO`：Serve Feature Window v0.4 自動選取主要動作。
- `HUMAN`：人工先選取一次完整發球，再於區間內偵測主要揮拍階段。

人工完整動作區間保存在
`serve_action_windows.json`。

## 結論

1. 整支影片計算會受到準備、靜止、重播與剪輯影響，六支影片的流暢度皆被判為 `POOR`。
2. 動作視窗可明顯降低非動作片段對手腕速度變異的干擾。
3. 人工區間是完整單次動作的外層邊界；系統主要揮拍視窗是特徵計算用的內層邊界，兩者用途不同。
4. `SV_001` 是反手發球，排除於正手門檻校正。
5. `SV_003` 含多角度剪輯，排除於門檻校正。
6. `SV_004` 含剪輯與重播，只能條件式參考。
7. `SV_005`、`SV_006` 含放慢播放，不可直接用於絕對速度門檻校正。
8. 目前正常速度正手門檻仍缺乏足夠樣本，需要補錄單鏡頭、自然速度、單次完整發球。

## 持拍側規則

人工標注的 `racket_side` 優先於系統推估，並且必須同時控制：

- 報告顯示的持拍側。
- `active_side_estimate`。
- 揮拍路徑與速度特徵使用的手腕。

若人工未指定，才使用 `DominantHandTracker` 自動推估。

SV_006 在側面與慢速播放條件下，自動推估為左手，信心值為 0.8367；人工標注明確確認為右手。新版輸出保留自動估計作為稽核證據，但正式結果顯示為 `右手・人工確認`。
