# AI Motion Platform API Contract V2

Version: `2.0`
Backend API Version: `FastAPI 2.0.0`
Base Path: `/api/v1`

## 1. Purpose

This document defines the public integration contract for the AI Motion Platform backend.

Current platform flow:

```text
Video
  ↓
Motion Assessment
  ↓
PostgreSQL
  ↓
Competency Profile
  ↓
Competency Engine
  ↓
AI Coach
  ↓
Structured JSON
```

All endpoints return the common envelope:

```json
{
  "success": true,
  "data": {},
  "error": null
}
```

Failure responses use:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "ERROR_CODE",
    "message": "錯誤說明",
    "details": {}
  }
}
```

# 3. Motion Assessment API

## POST `/api/v1/motion-assessments`

Uploads a video and starts asynchronous motion analysis.

### Request

Content-Type:

```text
multipart/form-data
```

Fields:

| Field | Type | Required | Description |
|---|---|---:|---|
| `assessment_type` | string | Yes | `footwork`, `serve`, or `clear` |
| `user_id` | integer | Yes | Existing `USERS.user_id` |
| `video` | file | Yes | `.mp4` or `.mov` |
| `client_recorded_at` | string | No | Client recording timestamp |
| `notes` | string | No | Optional note |

### Example

```bash
curl -X POST \
  -F "assessment_type=serve" \
  -F "user_id=1" \
  -F "video=@dataset/serve/videos/SV_002.mov" \
  http://127.0.0.1:8000/api/v1/motion-assessments
```

### Success

HTTP `202 Accepted`

```json
{
  "success": true,
  "data": {
    "assessment_id": "ma_xxxxxxxxxxxxxxxx",
    "assessment_type": "serve",
    "status": "uploaded",
    "created_at": "2026-08-07T00:00:00+00:00",
    "status_url": "/api/v1/motion-assessments/ma_xxxxxxxxxxxxxxxx",
    "report_url": "/api/v1/motion-assessments/ma_xxxxxxxxxxxxxxxx/report"
  },
  "error": null
}
```

### Common Errors

| HTTP | Code | Meaning |
|---:|---|---|
| 400 | `VIDEO_REQUIRED` | Missing video |
| 400 | `INVALID_REQUEST` | Invalid request fields |
| 400 | `INVALID_ASSESSMENT_TYPE` | Unsupported motion type |
| 400 | `INVALID_VIDEO_FORMAT` | Unsupported or unreadable video |
| 404 | `USER_NOT_FOUND` | User does not exist |
| 413 | `VIDEO_TOO_LARGE` | File exceeds 100 MB |
| 422 | `VIDEO_DURATION_INVALID` | Video shorter than 3 seconds |

### Success

```json
{
  "success": true,
  "data": {
    "assessment_id": "ma_xxxxxxxxxxxxxxxx",
    "assessment_type": "serve",
    "status": "completed",
    "progress": 100,
    "current_stage": "completed",
    "created_at": "2026-08-07T00:00:00+00:00",
    "updated_at": "2026-08-07T00:00:05+00:00",
    "completed_at": "2026-08-07T00:00:05+00:00",
    "failure": null,
    "report_url": "/api/v1/motion-assessments/ma_xxxxxxxxxxxxxxxx/report"
  },
  "error": null
}
```

Possible states:

```text
uploaded
processing
completed
failed
```

### Error

HTTP `404`

```text
ASSESSMENT_NOT_FOUND
```

---

## GET `/api/v1/motion-assessments/{assessment_id}/report`

Returns the complete persisted motion report JSON.

The payload depends on the motion type but always includes the motion report contract generated by the corresponding engine.

Typical summary:

```json
{
  "summary": {
    "completed": true,
    "evaluation_status": "EVALUATED",
    "overall_score": 74,
    "system_confidence": 1.0,
    "coach_status": "PASS"
  }
}
```

The public `assessment_id` is always the API ID:

```text
ma_...
```

The original internal engine assessment ID is preserved under:

```text
meta.engine_assessment_id
```

### Common Errors

| HTTP | Code | Meaning |
|---:|---|---|
| 404 | `ASSESSMENT_NOT_FOUND` | Assessment does not exist |
| 409 | `REPORT_NOT_READY` | Assessment is not completed |
| 500 | `ANALYSIS_FAILED` | Completed task has no report JSON |

# 6. Competency APIs

## POST `/api/v1/competency-profiles`

Legacy / explicit-ID competency endpoint.

This endpoint requires three completed assessment IDs.

### Request

```json
{
  "player_id": "demo_player",
  "footwork_assessment_id": "ma_...",
  "serve_assessment_id": "ma_...",
  "clear_assessment_id": "ma_..."
}
```

### Purpose

Useful for:

```text
manual integration
debugging
explicit report selection
```

For normal product flow, prefer:

```text
POST /api/v1/users/{user_id}/competency
```

---

## POST `/api/v1/competency-profile-reports`

Builds the dashboard-oriented Competency Profile Report from three explicit assessment IDs.

Input contract is identical to `/competency-profiles`.

---

### Important Design Rule

V1 does **not** calculate:

```text
cross-motion overall score
official badminton level
suggested playing level
```

The current competency layer is a self-motion skill profile.

### Error

HTTP `409`

```text
COMPETENCY_NOT_READY
```

Returned when one or more required motion reports are missing.

Example details:

```json
{
  "missing_motions": ["footwork"],
  "available_motions": ["clear", "serve"]
}
```

# 7. AI Coach API

## POST `/api/v1/users/{user_id}/coach`

Builds the AI Coach JSON from:

```text
latest motion reports
↓
Competency Profile
↓
Competency Interpretation
↓
AI Coach Engine
```

No request body is required.

```json
  "success": true,

    "coach_version": "ai-coach-v1.0",
    "rule_version": "ai-coach-rule-v1.0",
    "status": "READY",
    "player_id": "1",
    "strengths": [
      {
        "motion_type": "clear",
        "score": 86.0,

      },
      {
        "motion_type": "serve",

        "coach_status": "PASS",

        "recommendation": "優先加強步法穩定、回位與動作一致性。",
        "source": {
          "score": 77.0,
          "coach_status": "NEEDS_REVIEW",
          "assessment_id": "ma_..."
        }
      }
    ],
    "suggested_playing_level": {
      "status": "INSUFFICIENT_EVIDENCE",
      "suggested_range": null,
      "confidence": null
    },
    "limitations": []
  },
  "error": null

```

### Suggested Playing Level Policy

Current V1 intentionally returns:

```text
INSUFFICIENT_EVIDENCE
```

because isolated motion assessments do not represent complete game ability.

A future suggested playing level may use:

```text
Motion Competency
+
Game / Rally Competency
+
Evidence Coverage
```

It will remain an AI recommendation, not an official ranking.

# 8. Database Integration Contract

Current AI Motion backend uses:

```text
USERS
1
↓
many
VIDEO_ANALYSES
```

The AI module expects an existing user before a video analysis can be created.

Primary application identifier:

```text
video_analyses.external_analysis_id
```

Format:

```text
ma_...
```

The complete motion report is persisted in:

```text
video_analyses.metrics_json
```

using PostgreSQL `JSONB`.

Frequently consumed structured columns include:

```text
user_id
external_analysis_id
analysis_type
processing_status
progress
current_stage
overall_score
feedback
model_version
rule_version
created_at
updated_at
completed_at
```

# 9. Integration Responsibility

## AI Motion Backend

Responsible for:

```text
video analysis
motion scoring
report JSON
competency interpretation
AI Coach recommendation
```

## Frontend / LINE / Other Clients

Responsible for:

```text
display
interaction
upload UI
polling status
rendering dashboard
rendering coach recommendations
```

Clients should not duplicate backend scoring or competency rules.

# 10. Environment

Local development uses:

```env
DATABASE_URL=postgresql://username:password@localhost:5432/database_name
```

The application reads `.env` locally.

`.env` must not be committed.

`.env.example` is the shared configuration template.

When moving to Cloud SQL, the application contract remains unchanged; only the deployment environment database connection changes.
